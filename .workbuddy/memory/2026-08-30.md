# 2026-08-30

## NPCBotEquipment 插件跨客户端兼容兜底

排查「别人机器上一直卡在读取装备信息」问题，结论：客户端版本/API 差异会触发 Lua 报错（`SetShown`、`SetDesaturated`、`GetFont` 返回空等），报错后快照渲染中断，界面停留在"正在读取装备"。主快照请求本身没有超时处理（`requestDeadline` 只用于候选面板）。

本次修改（低侵入，只改客户端 Lua，不动服务端协议）：
- `addons/NPCBotEquipment/NPCBotEquipmentClient.lua`：新增兼容层并挂到 `_G.NPCBotEquipmentUI`：
  - `SafeSetShown(widget, shown)`：优先 SetShown，缺失回退 Show/Hide。
  - `SafeSetDesaturated(texture, on)`：缺失静默忽略。
  - `SafeAdjustFontSize(fontString, sizeOffset)`：GetFont 取不到字体路径/字号/标志时用默认字体（`STANDARD_TEXT_FONT` → `GameFontNormal:GetFont()` → `"Fonts\\FRIZQT__.TTF"`，字号 12，OUTLINE）。
  - 替换本文件所有 `:SetShown(`、`:SetDesaturated(` 直接调用点，以及槽位装等字号的 `GetFont` 逻辑。
- `NPCBotEquipmentAttributes.lua`：复用 `UI.SafeSetShown` / `UI.SafeAdjustFontSize`（本地降级兜底），替换 `specValue` 字体放大逻辑和 `attributesPanel:SetShown`。
- `NPCBotEquipmentManagement.lua`：复用 `UI.SafeSetShown`，替换非 EditBox 的 SetShown（职责/阈值/角度/走位等控件）。原有 `SafeEditBoxSetShown/SafeEditBoxSetEnabled` 保留。

校验：自写 Python 脚本做括号 + `function/if/for/while/repeat ↔ end/until` 块结构平衡检查，三个文件均通过（项目内无 lua/luac 可做真实语法解析）。

未处理（后续可做，需用户确认）：主快照请求超时兜底、`UIPanelDialogTemplate` 等模板存在性检测、`UnitGUID` 格式跨客户端兼容。
