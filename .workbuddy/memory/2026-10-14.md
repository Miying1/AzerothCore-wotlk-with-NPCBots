### 修正：盗贼默认构筑点数从「满配 89-93 点」改为「玩家规则 71 点」

**用户指出的问题**：默认天赋点超出常规点数太多。核实后确认这是我的理解错误，已修正。

**根因**：把方案「点数不设上限」误读为「规划时应按满配写」。实际语义是**声明上限不设（构筑写 120 点也不报错）**，**不是撰写指引**。默认构筑是给人看、供玩家对照攻略的静态数据，应按玩家 71 点规则构建。

**满配写法的两个实际危害**（写进方案 391 行澄清块）：
1. 截断只切尾 → 被切掉的恰是副系核心输出点（双武器专精、无情打击、致命偷袭），留下的反而是主系低价值填充 → **取舍逻辑反转**。
2. 玩家无法用游戏内天赋模拟器核对点数。

**修正结果**：三系重建为 **71 点（主系 51 + 副系 20）**，按用户选定的标准 51/20 流派：
- 刺杀 spec 10 = 毁伤流：主系刺杀 51（到 row8 毁伤）+ 副系战斗 20（双武器专精5/强化影袭2/偏斜3/精确5/近身格斗5）

雕文方案不变（大雕文 影袭409/切割410 + 专精位 毁伤733 或 剑刃乱舞394 或 背刺393；小雕文 466/469/468）。

**第二个误读也一并澄清**：「逐级回放」是**校验手段**（验证序列每个前缀合法），**不是运行时应用流程**。应用时直接取有序序列前 `A(等级)` 项即可，「取前缀」天然合法，无需模拟过程。我此前误当成运行时流程，还自己造出一个「跨树层级门槛会卡死」的伪问题——实际不存在。方案 640 行已加澄清。

**交付**：`tools/talent_url.py`（通用，全 10 职业）+ `tools/talent_data.json`（10 职业天赋树）+ `tools/glyph_data.json`（345 条雕文）。

**三系盗贼链接（实测往返一致，含天赋+雕文）**：
- 刺杀 51/13/7：`https://80.wowdb.cc/?talent#f0ecojgoVboIuVo0xV0hZxb:TIpVzc`
- 战斗 20/51/0：`https://80.wowdb.cc/?talent#f0eb0tLZMgVoxcxoru0xRt:pNVVzc`
- 敏锐 19/0/52：`https://80.wowdb.cc/?talent#f0eb0thZZxbcdhGzdAzqcRt:pAhVzc`

**URL 编码算法（逆向自站点 TalentCalc.js，与 wowhead/evowow 同源，勿凭记忆重推）**：
- 编码表 `0zMcmVokRsaqbdrfwihuGINALpTjnyxtgevElBCDFHJKOPQSUWXYZ123456789`；树分隔符 `Z`
- 职业前缀 = `ENCODING[oldId*3]`；oldId：德鲁伊0 猎人1 法师2 圣骑士3 牧师4 **盗贼5** 萨满6 术士7 战士8 死骑9
- 树内：rank（含 0）按槽位顺序拼数字串 → 去尾 `0` → 奇数补 `0` → 每 2 位 `ENCODING[d0*6+d1]`
- **尾部分隔符判据 `i < slot_count` 比较的是「补齐后的数字位数」，不是编码字符数**（写成字符数会多输出一个 Z）
- **空树也必须输出 `Z`**（因 `0 < slot_count`）；整个 build 末尾去尾部 `Z`
- **雕文段与天赋段用 `:` 分隔**（`talent.js` 的 `location.hash.substr(1).split(':')` → pounds[0]=build, pounds[1]=glyphs）
- 雕文段：按 `_glyphOrder=[1大,2小]` 分组，每组用 `ENCODING[g_glyphs[itemId].index]`，按 `_glyphLevels` 长度（大 3 / 小 3）判断补 `Z`
- 雕文槽位：0/3/5 = 大，1/2/4 = 小（**BUILTIN 的 glyphs 列表必须按 [大0,小1,小2,大3,小4,大5] 顺序**，按 0..5 直读会报槽位类型不匹配）

**关键坑：通过 URL hash 打开页面后不能立即读取数据**。`tc_readPound` 是 1 秒轮询，页面 JS 初始化未完成时读到的是中间态——曾因此误判战斗系 43 点、敏锐系 0 点、hash 被截断，实际编码全部正确。核对应等页面标题出现正确点数，或直接 `$WowheadTalentCalculator.setWhBuild(code)` 验证编码本身（该方式即时返回且往返一致）。

**另一个工具 bug（已修）**：`TREE_ALIAS` 原映射 `'1'→0,'2'→1,'3'→2` 与文档「0/1/2」不符，导致 `--talent "0:2:5"` 报"树标识无效"。已改为 `'0'→0,'1'→1,'2'→2`（保留 A/B/C 与 T0/T1/T2 别名）。

**清理**：已删除 `tools/talent_data_raw.txt`、`tools/glyph_data_raw.txt` 及临时下载的 JS。
