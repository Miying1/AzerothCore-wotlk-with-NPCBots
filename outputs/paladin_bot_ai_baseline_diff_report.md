# 圣骑士 BOT 战斗逻辑与基线差异分析

## 1. 对比范围

- 当前分支：`merge_test2_from_npcbots`
- 当前提交：`024831590`（`HEAD`）
- 权威基线：`upstream/npcbots_3.3.5@d914b8288`
- 对比文件：`src/server/game/AI/NpcBots/bot_paladin_ai.cpp`
- 差异规模：41 行新增、33 行删除（74 行差异）
- 工作树状态：该文件没有未提交修改
- 格式检查：`git diff --check upstream/npcbots_3.3.5...HEAD -- src/server/game/AI/NpcBots/bot_paladin_ai.cpp` 通过

`d914b8288` 是当前 `HEAD` 与 `upstream/npcbots_3.3.5` 的 merge-base，因此可以作为本次比较的稳定基线。差异中有一部分只是枚举项后增加中文注释，不改变运行时行为；真正的战斗语义集中在圣印解锁、职业被动光环和相关数值效果。

## 2. 总体结论

当前圣骑士版本不是对 `UpdateAI()` 或 `DoNormalAttack()` 的完整轮转重写。它保留了基线的主要战斗、治疗、辅助和保护流程，但通过额外技能/光环改变了角色的数值面板与圣印选择：

1. 防护专精在 20 级后额外获得命令圣印；
2. 防护专精重新启用 `Combat Expertise`，并额外获得坚韧、偏斜、神圣之力；
3. 惩戒专精额外获得神圣之力和定罪；
4. 新增被动大多通过 `RefreshAura()` 强制施加，因而不依赖真实天赋树加点；
5. 防护专精的技能优先级、嘲讽、减伤和近战攻击顺序基本没有改变，但这些被动会显著增强防骑的护甲、招架、耐力、精准、力量和暴击；
6. 其中 `49789` 和 `16466` 分别是死亡骑士/战士的同名或近似被动法术 ID，属于定制跨职业复用，必须确认这是有意设计，而不是技能 ID 误配。

因此，当前版本更准确的描述是：

> “基线战斗决策 + 额外的专精数值强化 + 防骑命令圣印扩展”，而不是新的圣骑士 AI 轮转。

## 3. 差异一：防护专精获得命令圣印

### 3.1 代码变化

当前版本：

```cpp
/*Talent*/lvl >= 20 && (isRetr||isProt) ? InitSpellMap(SEAL_OF_COMMAND_1) : RemoveSpell(SEAL_OF_COMMAND_1);
```

基线版本：

```cpp
/*Talent*/lvl >= 20 && isRetr ? InitSpellMap(SEAL_OF_COMMAND_1) : RemoveSpell(SEAL_OF_COMMAND_1);
```

也就是说，当前版本把命令圣印从“惩戒专精专属”扩展为“惩戒或防护专精可用”，等级门槛仍为 20 级。

### 3.2 对 `CheckSeal()` 的直接影响

`CheckSeal()` 中防护专精的选择顺序为：

```cpp
SEAL = COMMAND ? COMMAND : JUSTICE ? JUSTICE : RIGHT;
```

但在进入这个分支前，代码还会执行两类覆盖：

```cpp
if (VENGEANCE && victim &&
    (victim->GetMaxHealth() > me->GetMaxHealth() * (2 + victim->getAttackers().size() / 2) ||
    victim->GetClass() == CLASS_ROGUE))
    COMMAND = VENGEANCE;
```

以及低法力处理：

```cpp
if (IsMelee() && GetManaPCT(me) < 20 && WISDOM)
    SEAL = WISDOM;
```

所以防骑的实际优先级大致是：

1. 低法力时优先智慧圣印；
2. 特定高生命值目标或盗贼目标时，将命令圣印变量替换为复仇/腐蚀圣印；
3. 其他正常坦克场景优先命令圣印；
4. 没有命令圣印时，才考虑正义圣印；
5. 最后退回正义圣印/公正圣印 `RIGHT`。

### 3.3 实战影响

- 防骑不再以正义圣印或公正圣印作为普通场景的默认选择；
- 命令圣印的群体伤害/额外神圣伤害行为可能提高多目标仇恨和清怪速度；
- 对单目标坦克，命令圣印也可能改变普攻附带伤害与持续仇恨曲线；
- 面对高血量目标或盗贼目标时，代码可能选择复仇/腐蚀圣印，以便通过叠层或针对性效果获得更高收益；
- 低法力下仍会切到智慧圣印，因此该改动不会完全取消原有的资源自救逻辑。

### 3.4 评价

这是明确的策略强化，不是 `CheckSeal()` 主体算法改变。风险在于：命令圣印对防骑是否符合本项目的定制设计目标，以及它是否会与防骑原本依赖正义圣印的仇恨模型发生冲突。若目标是让防骑具备更强的 NPCBot 清怪和拉怪能力，该修改合理；若目标是严格还原 WotLK 标准专精，应该恢复基线条件。

## 4. 差异二：防护专精重新启用 Combat Expertise

### 4.1 代码变化

基线中该光环被注释：

```cpp
//RefreshAura(COMBAT_EXPERTISE, isProt && level >= 45 ? 1 : 0);
```

当前版本启用：

```cpp
RefreshAura(COMBAT_EXPERTISE, isProt && level >= 45 ? 1 : 0);
```

### 4.2 实际效果

`Combat Expertise = 31860` 的实际法术效果为：

- 精准提高 6；
- 总耐力提高 6%；
- 暴击提高 6%。

### 4.3 实战影响

- **生存**：6% 总耐力直接提高生命池，并增强依赖生命值的被动/技能收益；
- **仇恨**：精准提高可减少近战攻击被闪避/招架的概率，使平砍、近战技能和相关附带效果更稳定；
- **输出**：额外 6% 暴击提高普通攻击和部分可暴击技能的伤害/触发频率；
- **等级窗口**：从 45 级开始生效，属于中后期防骑的显著面板强化。

### 4.4 评价

这是本文件中影响最直接、且最容易被误认为“只是恢复基线”的差异。实际上基线已经主动注释了该项，因此当前版本是重新开启一项强力的额外被动。它同时作用于生命、命中质量和暴击，不能只按单一属性增益评估。

## 5. 差异三：防护专精新增坚韧与偏斜

当前新增：

```cpp
RefreshAura(JIANRENG, isProt && level >= 55 ? 1 : 0);
RefreshAura(PIANXIE, isProt && level >= 25 ? 1 : 0);
```

### 5.1 `JIANRENG = 49789`

经核实，`49789` 实际对应死亡骑士 Rank 5 `Toughness`，效果为：

- 物品提供的护甲提高 10%；
- 受到的减速效果持续时间降低 30%。

它不是圣骑士防护天赋树中按常规命名直接对应的法术 ID，但效果本身对坦克非常有价值。

**实战影响：**

- 提高来自装备的护甲，降低物理伤害；
- 对近战首领、普通物理攻击和依赖护甲减伤的场景有稳定收益；
- 减少减速持续时间，改善追怪、贴近目标和 PvP 机动性；
- 它不等同于提高所有伤害减免，对法术伤害收益有限。

### 5.2 `PIANXIE = 16466`

经核实，`16466` 实际对应战士 Rank 5 `Deflection`，效果为：

- 招架提高 5%。

WotLK 圣骑士防护天赋树中同类 Rank 5 技能通常使用另一个圣骑士法术 ID（常见对应为 `20064`），因此这里存在明显的跨职业 ID 复用。

**实战影响：**

- 直接增加近战攻击被招架的概率；
- 减少部分物理伤害，并改善坦克面对近战目标时的稳定性；
- 招架通常还会影响近战攻击节奏和仇恨稳定性，但具体收益依赖核心的招架、攻击速度和递减实现；
- 对法术伤害和不可招架的特殊攻击没有帮助。

## 6. 差异四：防护与惩戒新增神圣之力

当前新增：

```cpp
RefreshAura(SHENSHENGZHILI, (isRetr || isProt) && level >=55 ? 1 : 0);
```

`SHENSHENGZHILI = 20266` 实际对应 Rank 5 `Divine Strength`，效果为：

- 总力量提高 15%。

### 对防护专精

- 提高近战攻击强度，增加平砍与部分基于攻击强度的技能伤害；
- 提高命令圣印、复仇/腐蚀圣印以及其他近战相关附带伤害的收益；
- 进一步提高仇恨，尤其与命令圣印和精准强化叠加时更明显；
- 具体格挡值收益取决于核心对力量到格挡的换算和版本规则，不应直接假定为固定百分比格挡提升。

### 对惩戒专精

- 提高双手武器近战攻击强度；
- 增强十字军打击、神圣风暴、普通攻击和与攻击强度相关的圣印伤害；
- 与惩戒已有的武器专精、复仇、正义复仇等效果叠加后，输出会明显高于只有标准天赋映射的基线。

### 评价

这不是 AI 决策路径变化，而是全局战斗数值变化。55 级后防护和惩戒都会受到影响，属于明显的定制强化。

## 7. 差异五：惩戒专精新增定罪

当前新增：

```cpp
RefreshAura(DINGZUI, isRetr && level >=75 ? 1 : 0);
```

`DINGZUI = 20121` 实际对应 Rank 5 `Conviction`，效果为：

- 物理和法术暴击提高 5%。

### 实战影响

- 直接提高惩戒近战攻击和物理技能暴击率；
- 提高可暴击的神圣法术/审判/圣印相关伤害的暴击概率；
- 增强爆发窗口，并提高复仇、正义复仇等依赖暴击触发或暴击伤害的实际表现；
- 从 75 级才开始生效，主要影响满级或高等级惩戒 BOT。

### 评价

当前文件其他位置已经存在针对惩戒的暴击与伤害加成，例如 `Sanctified Wrath`、`Fanaticism`、`The Art of War` 等。`Conviction` 会与这些效果叠加，因此其总体作用是显著提高惩戒的终局输出上限，而不是改变技能释放顺序。

## 8. 与基线一致的战斗主流程

忽略枚举注释和上述被动/圣印差异后，以下主流程没有发现直接变化：

### 8.1 `UpdateAI()` 调度顺序

当前仍按基线执行：

1. `GlobalUpdate()`；
2. 载具动作与载具攻击判定；
3. 药水、低法力处理和神圣恳求；
4. 群体治疗、驱散、祝福、圣盾和牺牲之手等辅助行为；
5. 脱战复活；
6. `CheckSeal()` 和 `CheckAura()`；
7. 即时非攻击目标处理；
8. 攻击目标检查；
9. 悔罪、反制、超度邪恶、神圣干涉；
10. 物品处理；
11. `DoNormalAttack()`。

这意味着新增的被动只改变战斗结果，不会让圣骑士改变“先治疗还是先输出”“先嘲讽还是先打击”等基础决策顺序。

### 8.2 `DoNormalAttack()` 顺序

当前主要优先级仍为：

1. 圣盾术等低生命自保；
2. 神圣之盾；
3. 愤怒之锤；
4. 嘲讽与正义防御；
5. 神圣恳求；
6. 复仇之怒；
7. 复仇者之盾；
8. 圣佑术；
9. 驱邪术；
10. 制裁之锤；
11. 审判；
12. 奉献；
13. 正义之锤；
14. 正义盾击；
15. 十字军打击；
16. 神圣风暴；
17. 神圣愤怒。

当前没有证据表明这些技能的条件、距离、随机门槛、目标过滤或先后顺序相对基线发生了新的直接变化。

## 9. 治疗与辅助流程没有直接变化

以下功能在本次文件差异中没有发现主逻辑改写：

- `HealTarget()` 及闪现治疗、圣光术、圣疗术、圣光震击的选择；
- `BuffAndHealGroup()` 群体治疗与祝福；
- `CureGroup()` 清洁术/净化术；
- `CheckHandOfSacrifice()` 牺牲之手；
- `HOFGroup()` 自由之手；
- `HOSGroup()` 保护之手；
- `ShieldGroup()` 圣盾/圣盾类辅助；
- `CheckDivineIntervention()` 神圣干涉；
- 光环选择与团队增益逻辑；
- `Righteous Fury` 对防护专精的开关逻辑。

需要区分的是：文件中本来就有大量自定义的技能效果修改，例如圣盾吸收、光环效果、祝福数值、治疗加成和冷却缩减。这些并不是本次相对基线新增的主差异，不能把它们误归因于本次变更。

## 10. 对四类实战表现的综合评估

### 10.1 输出

- 防骑：命令圣印、15% 力量、6% 暴击和 6 点精准共同提高近战与圣印相关伤害；
- 惩戒：15% 力量与额外 5% 暴击使高等级输出明显高于基线；
- 技能优先级未变，因此提升表现为“同样轮转下每个动作更强”，而非动作更多；
- 防骑在多目标场景中的命令圣印收益尤其值得重点测试。

### 10.2 生存

- 防骑 6% 总耐力、10% 装备护甲、5% 招架共同提升物理承伤能力；
- 减速持续时间缩短改善移动和接怪，但不属于传统减伤；
- 原有炽热防御者、盾牌壁垒、神圣守护者等基线自定义效果仍然存在，新增强化会与它们叠加；
- 物理型首领战中增强最明显，法术型伤害和不可规避机制收益较小。

### 10.3 仇恨

- 精准减少攻击被闪避/招架的机会，提升仇恨连续性；
- 力量提高攻击强度，命令圣印提高附带伤害，三者具有叠加效应；
- 仇恨提升主要来自面板数值和圣印，不来自额外嘲讽次数；
- 嘲讽和正义防御的目标筛选、随机门槛及 Boss 排除规则没有直接变化。

### 10.4 PvP

- 防骑拥有额外护甲、招架、耐力和力量，近战对抗能力明显增强；
- 减速持续时间降低会提高追击和脱离减速的能力；
- 命令圣印可能增加短时间爆发，但其群体/附带伤害在 PvP 中仍需验证是否会错误破控；
- 定罪只作用于惩戒专精，惩戒 BOT 的爆发和暴击压力会进一步增加；
- 本文件的差异没有新增 PvP 目标判断或专门 PvP 轮转。

## 11. 跨职业法术 ID 风险

### 高风险：`49789`

- 名称/效果对应死亡骑士 `Toughness`；
- 当前被作为防护圣骑士被动直接 `RefreshAura()`；
- 如果未来数据库或核心调整该法术的职业限制、效果索引或目标条件，可能出现效果消失或行为不一致；
- 更稳妥的方式是确认项目是否已有专门的圣骑士定制被动 ID，或在自定义技能表中建立明确的 NPCBot 专用效果。

### 高风险：`16466`

- 实际对应战士 `Deflection`；
- 当前作用是 5% 招架；
- 圣骑士同类天赋通常有不同法术 ID；
- 需要确认这里不是把旧版本/其他职业 Rank 5 ID 误填进圣骑士枚举。

### 中风险：`20266` 与 `20121`

- 这两个 ID 的效果本身与“神圣之力”和“定罪”的预期一致；
- 但它们同样是直接跨用数据库中的职业天赋法术效果，而不是由真实天赋树授予；
- 若项目有意做 NPCBot 全职业强化，这种做法可以保留；若追求标准职业映射，应改用明确、可维护的专用效果来源。

### 维护性风险

这些 ID 的注释目前只写了中文简称或 `rank`，没有注明实际来源职业。后续维护者可能误以为它们都是圣骑士原生技能。建议在代码注释中明确标注来源，例如“DK Toughness rank 5”或“Warrior Deflection rank 5”，并在需要时补充效果验证。

## 12. 风险优先级与建议

### P0：确认跨职业 ID 是否为有意设计

优先确认：

- `49789` 是否确实要给予防骑 10% 装备护甲和减速抗性；
- `16466` 是否确实要给予防骑 5% 招架；
- `20266` 是否确实要同时给予防骑和惩戒 15% 力量；
- `20121` 是否确实要给予惩戒额外 5% 全暴击。

若答案为“是”，建议补充来源职业、效果和设计意图注释；若答案为“否”，应恢复对应基线逻辑或改用正确的圣骑士技能 ID。

### P1：实战验证防骑命令圣印

重点测试：

- 单目标首领：命令、复仇/腐蚀和正义圣印的仇恨对比；
- 两个以上攻击者：`JUSTICE` 被清零后命令圣印是否符合预期；
- 低法力：是否及时切换智慧圣印并恢复资源；
- 高血量目标与盗贼目标：复仇/腐蚀圣印覆盖命令圣印是否会频繁切换；
- PvP：命令圣印附带伤害是否会破坏控制或误伤非目标单位。

### P1：验证防骑生存与仇恨是否超出设计上限

建议记录相同装备、相同等级和相同首领条件下的：

- 最大生命值；
- 装备护甲与最终物理减伤；
- 招架率；
- 精准/未命中/被闪避情况；
- 单目标与多目标 TPS；
- 受到物理和法术伤害的有效生命时间。

### P2：仅做维护性清理

- 补充跨职业技能 ID 的来源注释；
- 将 `lvl >=55`、`lvl >=75` 等新条件统一为项目风格的空格形式；
- 保持 `git diff --check` 无输出。

本次不建议直接重写 `DoNormalAttack()` 或治疗流程，因为当前对比没有证据表明这些流程被本次变更破坏。

## 13. 最终评价

当前 `bot_paladin_ai.cpp` 相对基线的核心变化可以概括为：

- **防骑圣印**：20 级起新增命令圣印，普通坦克场景的圣印优先级因此发生变化；
- **防骑生存**：45 级起获得 `Combat Expertise`，55 级起获得额外护甲和力量，25 级起获得额外招架；
- **惩戒输出**：55 级起获得额外力量，75 级起获得额外 5% 物理/法术暴击；
- **战斗轮转**：主要技能优先级、嘲讽、治疗、保护、祝福、光环和自保流程基本保持基线行为；
- **代码风险**：最大问题不是轮转错误，而是跨职业法术 ID 带来的意图不明确、数据库兼容性和后续维护风险。

结论：当前版本是“保留基线 AI 决策、显著增强防护与惩戒面板”的定制版。若项目目标是强化 NPCBot，改动方向一致；若项目目标是还原标准 WotLK 职业边界，则应优先复核命令圣印扩展和四个新增被动，尤其是 `49789`、`16466` 两个跨职业 ID。
