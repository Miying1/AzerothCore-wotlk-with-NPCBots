# 个人银行保留 + 账号银行扩展方案

> 目标：在**完全保留现有个人银行**的前提下，**额外**增加一个「账号银行」（同账号下所有角色通用），并支持**按物品等级限制存入**。
> 客户端零改动；个人银行代码路径零改动；账号银行为纯增量功能。

---

## 1. 背景与目标

### 1.1 现状

- 个人银行归属单位为**角色 GUID**，物品存 `item_instance`（`owner_guid = 角色GUID`），位置存 `character_inventory`（`guid = 角色GUID`）。
- 角色之间银行互不相通。

### 1.2 目标

- **保留个人银行**：角色私有银行行为完全不变。
- **新增账号银行**：同账号角色共享一份银行（物品 + 背包 + 已购买背包槽数）。
- **物品等级限制**：账号银行只允许存入「物品等级 ≤ 阈值」的物品（阈值可配置，默认 232）。
- **客户端零改动**：复用同一套银行 UI 和协议。
- **入口**：银行 NPC gossip 菜单加一项「账号银行」。

### 1.3 核心矛盾与解法

客户端只有**一套**个人银行 UI（槽位 `39~74`）。要「额外加一个银行」且「保留个人银行」，本质是让这同一套 UI 在两个银行之间**切换**：

```
登录 → 默认个人银行（原逻辑）
点银行 NPC → gossip 菜单
   ├─「个人银行」→ 切到个人银行（原逻辑）
   └─「账号银行」→ 切到账号银行（新增逻辑）
```

---

## 2. 总体设计

### 2.1 架构

```
个人银行（不变）      账号银行（新增）
─────────────────    ─────────────────
character_inventory   account_bank_item
owner_guid = 角色     owner_guid = 0
m_items[39~74]        m_items[39~74]（切换时复用同一组槽位）
```

- `m_items[39~74]` 始终表示「当前显示的银行」。
- `Player::_bankMode` 区分当前是 `BANK_MODE_PERSONAL` 还是 `BANK_MODE_ACCOUNT`。
- 切换时「卸载当前银行 + 加载目标银行」，存/取/保存按 `_bankMode` 路由。

### 2.2 槽位布局（个人/账号银行共用）

| 槽位类型 | slot 范围 | 数量 |
|---|---|---|
| 银行物品槽 | 39 ~ 66 | 28 |
| 银行背包槽 | 67 ~ 74 | 7 |
| 银行背包内部 | bag=67~74, slot=0~N | 取决于背包容量 |

## 3. 客户端 UI 与协议（零改动原理）

### 3.1 打开流程

```
点银行 NPC → CMSG_BANKER_ACTIVATE（或 gossip 选项）
   → 服务端 SendShowBank(npcGuid) → SMSG_SHOW_BANK
   → 客户端打开银行界面
```

### 3.2 物品数据何时下发

个人银行物品**不是打开时拉取的**，而是在角色登录时作为角色对象字段下发：

- `StoreItem` 中 `SetGuidValue(PLAYER_FIELD_INV_SLOT_HEAD + (slot * 2), pItem->GetGUID())`
- 银行物品 GUID 存在 `PLAYER_FIELD_INV_SLOT_HEAD + slot*2`（slot=39~74）这个 update field。
- 客户端打开银行界面时，只渲染这些本地已有字段。

### 3.3 结论

| 环节 | 是否改动 |
|---|---|
| 打开 UI（`CMSG_BANKER_ACTIVATE` → `SMSG_SHOW_BANK`） | 不变 |
| 存/取协议（`CMSG_AUTO_BANK_ITEM` / `CMSG_AUTO_STORE_BANK_ITEM`） | 不变 |
| 物品下发（`PLAYER_FIELD_INV_SLOT_HEAD + slot*2`） | 不变 |
| gossip 菜单（新增「账号银行」选项） | 新增 |

## 5. gossip 入口实现

### 5.1 新增 CreatureScript

**文件**：`src/server/scripts/Custom/AccountBank/npc_account_bank.cpp`

```cpp
#include "ScriptedGossip.h"

// 账号银行 NPC：提供「个人银行 / 账号银行」切换入口
class npc_account_bank : public CreatureScript
{
public:
    npc_account_bank() : CreatureScript("npc_account_bank") { }

    // 打开 gossip 菜单
    bool OnGossipHello(Player* player, Creature* creature) override
    {
        AddGossipItemFor(player, GOSSIP_ICON_VENDOR, "我想使用个人银行",
                         GOSSIP_SENDER_MAIN, GOSSIP_ACTION_INFO_DEF + 1);
        AddGossipItemFor(player, GOSSIP_ICON_VENDOR, "我想使用账号银行",
                         GOSSIP_SENDER_MAIN, GOSSIP_ACTION_INFO_DEF + 2);
        SendGossipMenuFor(player, DEFAULT_GOSSIP_MESSAGE, creature->GetGUID());
        return true;
    }

    // 处理菜单选择
    bool OnGossipSelect(Player* player, Creature* creature, uint32 sender, uint32 action) override
    {
        if (sender == GOSSIP_SENDER_MAIN)
        {
            if (action == GOSSIP_ACTION_INFO_DEF + 1)
                player->SwitchBankMode(BANK_MODE_PERSONAL);   // 个人银行
            else if (action == GOSSIP_ACTION_INFO_DEF + 2)
                player->SwitchBankMode(BANK_MODE_ACCOUNT);    // 账号银行
        }

        player->PlayerTalkClass->SendCloseGossip();
        player->GetSession()->SendShowBank(creature->GetGUID());
        return true;
    }
};

void AddSC_npc_account_bank()
{
    new npc_account_bank();
}
```

### 5.2 脚本注册

在 `custom_script_loader.cpp` 中声明并调用 `AddSC_npc_account_bank()`。

## 6. 切换机制（核心）

### 6.1 Player 新增成员

**文件**：`src/server/game/Entities/Player/Player.h`

```cpp
// 银行模式
enum BankMode : uint8
{
    BANK_MODE_PERSONAL = 0,   // 个人银行（默认）
    BANK_MODE_ACCOUNT  = 1    // 账号银行
};

// 成员变量
BankMode _bankMode = BANK_MODE_PERSONAL;
uint8 _personalBankSlots = 0;   // 个人银行已购买背包槽数（缓存）
uint8 _accountBankSlots = 0;    // 账号银行已购买背包槽数（缓存）
```

### 6.2 切换函数

**文件**：`src/server/game/Entities/Player/PlayerStorage.cpp`

```cpp
void Player::SwitchBankMode(BankMode mode)
{
    if (_bankMode == mode)
        return;

    // 1. 保存当前银行未落库的改动（按当前 _bankMode 写对应表）
    _SaveInventory();

    // 2. 软卸载当前银行：RemoveItem 只是暂时取出，不改变物品、不删 DB
    //    卸载顶层银行槽位（物品槽 + 背包槽）
    for (uint8 slot = BANK_SLOT_ITEM_START; slot < BANK_SLOT_BAG_END; ++slot)
    {
        if (Item* item = m_items[slot])
        {
            RemoveItem(INVENTORY_SLOT_BAG_0, slot, false);
            item->RemoveFromUpdateQueueOf(this);   // 移出更新队列，避免后续误存
            delete item;                            // 数据已持久化，安全 delete
        }
    }
    // 注意：银行背包内物品随背包一起卸载（背包被 RemoveItem 时其内部物品需一并处理）

    // 3. 按目标模式加载对应银行到 m_items[39~74]
    _bankMode = mode;
    if (mode == BANK_MODE_PERSONAL)
        _LoadPersonalBank();    // 从 character_inventory 加载银行部分
    else
        _LoadAccountBank();     // 从 account_bank_item 加载

    // 4. 刷新背包槽数显示
    SetBankBagSlotCount(mode == BANK_MODE_PERSONAL ? _personalBankSlots : _accountBankSlots);
}
```

> `RemoveItem` 关键依据（`PlayerStorage.cpp:2985` 注释）：
> *"removeitem does not actually change the item; it only takes the item out of storage temporarily"* —— 不改变物品、不删 DB，正好匹配「切换」语义。

### 6.3 加载函数

- **`_LoadPersonalBank()`**：复用现有 `CHAR_SEL_CHARACTER_INVENTORY`（按角色 guid），回调中**只处理银行物品**（`IsBankPos`），其余跳过（普通物品已在 m_items，避免重复加载）。
- **`_LoadAccountBank()`**：使用 `CHAR_SEL_ACCOUNT_BANK_ITEM`（按 account_id），加载账号银行物品，owner 传空。

> `_LoadItem` 需增加 `ObjectGuid owner` 参数（默认 `GetGUID()`），账号银行物品传 `ObjectGuid::Empty`（见 7.4）。

## 8. 账号银行扩展：物品等级限制

> 需求：账号银行只允许存入「物品等级 ≤ 阈值」的物品，阈值可配置，默认 **232**。个人银行不受此限制。

### 8.1 配置项

采用项目规范的 `sConfigMgr->GetOption<T>()`（无需修改 `WorldConfig.h/cpp`），在 `worldserver.conf` 中增加一行即可：

```conf
#
#    账号银行扩展
#        AccountBank.MaxItemLevel
#        允许存入账号银行的物品等级上限（物品等级 <= 该值才能存入）
#        默认: 232
#
AccountBank.MaxItemLevel = 232
```

### 8.2 存入校验注入

**文件**：`src/server/game/Entities/Player/PlayerStorage.cpp` 的 `CanBankItem`（约 2115 行）

`CanBankItem` 是**所有「存入银行」操作的唯一校验入口**（`BankHandler.cpp` 中 `HandleAutoBankItemOpcode` 与 `HandleAutoStoreBankItemOpcode` 均经由此），在拿到 `pProto` 后插入：

```cpp
ItemTemplate const* pProto = pItem->GetTemplate();
if (!pProto)
    return EQUIP_ERR_ITEM_NOT_FOUND;

// 账号银行：按物品等级限制存入（个人银行不受限制）
if (_bankMode == BANK_MODE_ACCOUNT)
{
    uint32 maxItemLevel = sConfigMgr->GetOption<uint32>("AccountBank.MaxItemLevel", 232);
    if (pProto->ItemLevel > maxItemLevel)
        return EQUIP_ERR_CANT_DO_RIGHT_NOW;   // 物品等级超过上限，拒绝存入
}
```

### 8.3 物品等级字段

使用 `pProto->ItemLevel`（`ItemTemplate.h:635`，物品基础等级）。现有 `ItemDelete` 功能（`ItemHandler.cpp:1507`）即用 `GetTemplate()->ItemLevel`，语义一致。

### 8.4 错误提示（可选优化）

`EQUIP_ERR_CANT_DO_RIGHT_NOW` 客户端只显示通用提示。若需友好提示，在 `BankHandler.cpp` 调用处补一个飘字：

```cpp
// 在调用 CanBankItem 返回错误后
if (msg == EQUIP_ERR_CANT_DO_RIGHT_NOW && _player->GetBankMode() == BANK_MODE_ACCOUNT)
    _player->GetSession()->SendNotification("物品等级超过上限，无法存入账号银行");
```

> 需 `Player` 暴露 `GetBankMode()`（或直接在 `CanBankItem` 内 `SendNotification`）。

### 8.5 行为说明

| 场景 | 结果 |
|---|---|
| 物品等级 ≤ 232 存账号银行 | 允许 |
| 物品等级 > 232 存账号银行 | 拒绝 |
| 任意物品存个人银行 | 不受限制 |
| 从账号银行取出物品（取出走 `CanStoreItem`） | 不受限制 |

- 等级限制**只作用于存入**，取出不受影响（取出走 `CanStoreItem`，非 `CanBankItem`）。
- 个人银行完全不受影响（判断含 `_bankMode == BANK_MODE_ACCOUNT` 条件）。

## 9. 个人银行零影响保障

- 登录默认 `_bankMode = PERSONAL`，加载个人银行（**原逻辑一行不动**）。
- `SwitchBankMode`、`_LoadAccountBank`、物品等级限制都是**新增**逻辑，不侵入现有个人银行路径。
- 不点「账号银行」，玩家行为与现在完全一致（除了多一个 gossip 菜单）。

---

## 10. 关键难点与注意事项

1. **切换（软卸载）**：切银行时要「卸载」当前 `m_items[39~74]` 的 Item 对象（不 delete DB 数据），再「加载」目标银行。用 `RemoveItem` 实现，见 6.2。
2. **无「关闭」信号**：个人银行关闭时客户端不通知服务端，切换由「打开哪个 gossip 入口」驱动，不依赖关闭事件。
3. **背包容器内容也要账号化**：银行背包内物品（bag=67~74）必须一起切到 `account_bank_item`，不能只处理 28 个物品槽。
4. **物品 owner_guid 置空的影响**：账号银行物品 owner=0，需确认与公会银行物品（owner=0）行为一致；删除角色时 `CHAR_DEL_ITEM_INSTANCE_BY_OWNER` 不会误删（owner=0 不匹配角色 guid）。
5. **并发 / 多角色同时在线**：同账号两角色同时开账号银行有写冲突风险，建议限制同账号同时单角色在线，或加账号级互斥。
6. **孤儿数据**：账号最后一个角色删除后，`account_bank_item` / `item_instance(owner=0)` 成为孤儿，可接受或提供清理钩子。
7. **字段顺序强约束**：`CHAR_SEL_ACCOUNT_BANK_ITEM` 的 SELECT 字段顺序必须与 `CHAR_SEL_CHARACTER_INVENTORY` 完全一致，否则 `_LoadItem` 的 `fields[11..14]` 索引错位。

---

## 11. 测试要点

1. 单角色存取账号银行物品、放背包、背包内放物品，重启后数据不丢失。
2. 同账号 A/B 两角色：A 存物品 → B 登录后能看到同一物品；B 取出后 A 也看不到。
3. 已购买背包槽数量：A 购买 7 个槽 → B 登录后也是 7 个槽。
4. 个人银行回归：不点「账号银行」时，个人银行行为与改造前一致。
5. **物品等级限制**：物品等级 232 及以下可存入账号银行；233 及以上被拒绝；个人银行不受限制；从账号银行取出不受限制。
6. 删除角色 A：不影响账号银行物品（owner=0 不被误删）。
7. 公会银行功能回归：确认改动未影响公会银行。
