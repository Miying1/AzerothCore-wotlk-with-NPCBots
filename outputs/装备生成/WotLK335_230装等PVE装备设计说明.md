# WotLK 3.3.5：230装等PVE装备最终设计指南

## 1. 最终交付范围

- 共 **577 件**230装等史诗PVE装备，Entry `99423`–`99999`；SQL只生成，未执行。
- 排除饰品及全部职业圣物槽（圣契、神像、图腾、魔印）。
- 覆盖常规护甲、首饰、披风、副手、盾牌和实用武器；定位包含法系输出、力量输出、敏捷输出、治疗和坦克。
- 本批按用户要求不设置猫德、熊T专用定位或专用武器线；常规敏捷武器仍按敏捷输出模板生成。
- 每件至少有2种白字属性和2种绿字属性；名称全局唯一，不含任何数字及“布甲、皮甲、锁甲、板甲”，且每个名称最多使用一次“·”分隔符。

## 2. 数据范围与整件预算

1. 基准仅使用本地 `acore_world.item_template` 中 `213≤ItemLevel≤284` 的史诗PVE装备；排除韧性和法术穿透模板。
2. 一件新装备绑定一件完整基准装备，保留原模板属性条数、属性顺序和整件预算结构；禁止分别抽取单项中位数后拼装。
3. 不在模板预算外添加属性。缺少完全匹配模板时，只允许复用等价整件预算并占用原有评级槽位，回退类型和映射必须记录到CSV。
4. 精神不会替代耐力：凡保留精神的模板必须同时保留耐力。常规坦克装备允许纯生存或防御评级搭配命中/精准。

## 3. 230归一与最终随机

- 单项归一公式：`V230 = round(Vbase × EXP(kstat × (230 - ItemLevelbase)))`。各属性使用独立拟合系数；缺项才回退 `k=0.00733`。
- 武器伤害区间按武器分类DPS系数归一；投掷武器使用独立系数，不能套用弓/弩/枪。基础护甲使用 `k=0.00290`。
- 严格顺序：完整模板原值 → 230归一 → 必要的等价评级映射 → 每条绿字独立乘以 `Random(0.90, 1.10)` → 整数舍入。
- 固定属性随机种子 `33523008`，本批实际生效倍率范围 `0.9000`–`1.1000`；每条绿字的最终整数值严格限制在归一值的90%–110%整数边界内，白字不参与最后±10%。

- 战斗评级：防御 `0.00879858`、躲闪 `0.00741510`、招架 `0.00947473`、命中 `0.00999456`、暴击 `0.00971821`、急速 `0.00831172`、精准 `0.00908912`。

## 4. 模板回退机制

- 力量单手武器：若同子类缺输出模板，可用同子类坦克完整模板，将防御评级槽等价替换为命中、暴击、急速、精准或护甲穿透；不得增加属性条。
- 力量长柄：可复用同手位力量双手完整预算，仍保持原属性条数。
- 所有回退均写入清单的“预算回退方式”和“等价词条映射”；没有记录的装备不得改变模板属性类型。

## 5. 宝石插槽规则

- 使用独立固定种子 `33523010`，从全部577件中选取 **404件**带孔，占比 `70.02%`。百分比转整数统一采用四舍五入。
- 在404件带孔装备中，**121件**为2孔，占带孔装备 `29.95%`；其余 **283件**为1孔。未选中的173件为0孔。
- 插槽颜色只使用WotLK原生红色(2)、黄色(4)、蓝色(8)，按角色定位轮换；不生成棱彩槽，不预填宝石。
- 头部装备（`InventoryType=1`）统一清除原有插槽，改为1个混沌/变换槽（编码1），再随机附加1–2个红、黄、蓝槽；因此头部最终为2–3孔，`socketContent_1/2/3`和`socketBonus`均为0。
- 本批`socketBonus`统一为0：用户要求只增加插槽，未在原属性预算上额外增加插槽奖励，避免形成未计入模板的隐性绿字预算。

## 6. SQL、外观与命名

- SQL按当前本地表的 **138 列**完整显式列名生成，不含已移除的旧字段 `StatsCount`，不依赖物理列顺序。
- 外观来源仅限蓝、紫、橙品质且 `RequiredLevel=1–79`；按同class/subclass和兼容手位匹配，不使用80级装备外观。
- 同时生成8列增量 `Item.dbc.csv` 与合并基础 `Item.csv` 后可直接部署的完整二进制 `Item.dbc`（WDBC、8个32位整数字段）。
- 本批使用橙色武器外观 **28 个**，所有橙色武器 `displayid` 唯一；无可用唯一橙色外观时回退紫/蓝外观。
- 名称不使用任何数字，每件名称最多出现一次“·”分隔符；同时保持全局唯一，并禁止出现“布甲、皮甲、锁甲、板甲”。
- 不继承基准物品的触发法术、随机属性、套装、任务和脚本字段。
