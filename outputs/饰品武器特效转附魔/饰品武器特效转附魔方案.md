# 饰品特效转附魔道具方案

> 本文档已按**实际落地的代码**（`generate.py` + `src/TrinketEssence.cpp` + 两份 SQL）同步；
> 运行口径与字段取值以 `README.md` 和生成脚本为准。

## 1. 需求概述

将「饰品」上的**触发类特效（proc）**提取出来，制作为**附魔卷轴**，玩家使用卷轴后可将该特效**永久附魔到武器 0 槽位**。
另提供道具「**饰品特效提取器**」（60105，消耗品）：右键使用 → 列出背包里带可提取特效的饰品 → 选中一件 →
自动生成对应附魔卷轴，并销毁原饰品、消耗提取器本身。

范围约定（与 `generate.py` 顶部的配置常量一致）：

- 筛选表：本地库 `acore_world.item_template`；
- 物品等级 `ItemLevel >= 200`（`MIN_ITEM_LEVEL`）；
- 物品类别：`InventoryType = 12`（饰品栏，`INVENTORY_TYPE_TRINKET`）；
- 特效类型：`spelltrigger_1..5 = 1`（装备被动）或 `2`（命中触发）；
- **只保留真正的 proc 特效**（`Spell.csv` 中 `ProcTypeMask > 0`）；纯被动属性光环（`+治疗/+法伤/+攻强` 等）不做；
  `spelltrigger = 2` 由物品/附魔的 PPM 机制驱动，不受 `ProcTypeMask` 约束；
- 在 `Spell.csv` 中找不到定义的法术直接忽略；
- 道具形态：**附魔卷轴**（消耗品，右键使用 → 弹附魔窗口 → 选择武器 → 永久附魔到 0 槽位）。

> 原始需求曾覆盖「武器（`class = 2`）+ 饰品（`class = 4`）」，实测武器上的 proc 特效与本体强度绑定过深，
> 故**落地范围收敛为仅饰品**（`InventoryType = 12`）。若日后要纳入武器，改 `generate.py` 的范围常量即可，
> 运行时逻辑不受影响。

## 2. 数据摸底（实测）

统计范围：`item_template` 中 `ItemLevel >= 200` 且 `InventoryType = 12`，跨 5 个法术槽
（`spellid_1..5` / `spelltrigger_1..5`），按法术 ID 去重后的结果：

| 项 | 数量 | 说明 |
| --- | ---: | --- |
| 装备被动（`trigger = 1`）去重法术 | — | 其中 `ProcTypeMask > 0` 的为真 proc，其余为纯被动属性光环 |
| 击中触发（`trigger = 2`）去重法术 | — | 全部为 proc 特效 |
| **最终纳入（真 proc 特效）** | **78** | 全部为 `trigger = 1`；本批**没有** `trigger = 2`，故 `spell_enchant_proc_data` 为空 |

逐条明细（附魔 ID / 附魔法术 ID / 卷轴 entry / 原特效法术 / 触发类型 / 显示名 / 来源饰品）
由脚本输出到同目录的 `可用饰品特效清单.csv`；被排除的法术在运行时逐条打印，不落盘。

## 3. 技术链路

附魔/附魔法术的 DBC 数据由客户端 DBC 提供（见 4.1），服务端与客户端读同一份文件。整条链路如下：

```
饰品 proc 特效 spell (item_template.spellid_i + spelltrigger_i)
   │  只取 spelltrigger=1（本批）；trigger=2 时映射为 COMBAT_SPELL + proc 数据
   ▼
SpellItemEnchantment 条目  ──  trigger=1 → Effect=3 EQUIP_SPELL
   │                           trigger=2 → Effect=1 COMBAT_SPELL + proc 数据
   │  EffectArg_1 = 原特效 spell 的 ID（效果完全复用原法术，不复制定义）
   ▼
附魔法术 (Spell, Effect_1=53 ENCHANT_ITEM, EffectMiscValue_1=附魔ID)
   │  客户端据此弹出「附魔窗口」，服务端 EffectEnchantItemPerm 落到 0 槽位
   ▼
附魔卷轴 (item_template: class=0 / subclass=8, spellid_1=附魔法术, spelltrigger_1=0)
```

### 3.1 附魔效果类型映射

| 原特效类型 | 附魔 `Effect_1` | 附魔 `EffectArg_1` | proc 数据 | 触发机制 |
| --- | ---: | --- | --- | --- |
| 装备被动（`trigger = 1`） | `3` EQUIP_SPELL | 原特效 spell ID | 不需要 | 装备武器时施加原 proc 光环，由光环自身 `ProcTypeMask`/`ProcChance` 触发 |
| 击中触发（`trigger = 2`） | `1` COMBAT_SPELL | 原特效 spell ID | 需要 | 击中时按 `spell_enchant_proc_data` 的 PPM 触发 |

关键点：

- **EQUIP_SPELL**：走 `Player::ApplyItemEquipSpell`，装备武器时把 `EffectArg_1` 指向的原法术作为光环施加给玩家；
  原法术本身是 proc 光环，触发逻辑完全复用，**无需** `spell_enchant_proc_data`。
- **COMBAT_SPELL**：走 `Player::CastItemCombatSpell`，需要 `spell_enchant_proc_data` 提供 PPM
  （`PPMChance` 取原物品的 `spellppmRate`）。**本批 78 条全部是 EQUIP_SPELL，该表为空**。

### 3.2 附魔到 0 槽位

`SpellEffects.cpp` 的 `EffectEnchantItemPerm` 中，`EffectMiscValue` 即为附魔 ID，
最终写入 `Item::PERM_ENCHANTMENT_SLOT`（0 槽位）。因此每个附魔需要配一个 `ENCHANT_ITEM`（Effect=53）附魔法术，
其 `EffectMiscValue_1` 指向附魔 ID。

### 3.3 运行时（`src/TrinketEssence.cpp`）

```
使用「饰品特效提取器」(60105)
   → 扫描主背包(16 格) + 已装备包内的物品，只取 InventoryType = 12（不含已装备的饰品）
   → 两段过滤，先装等后查表：
        1) 装等：ItemLevel < MIN_TRINKET_ITEM_LEVEL(200) 直接跳过（不再扫法术槽）
        2) 查表：逐个读 item_template.spellid_1..5，法术 ID 在 mod_trinket_essence_map 里 = 可提取
   → 列表里显示的是饰品名；每件只取「第一个命中」的法术槽，只生成 1 张卷轴
   → 先校验落位（GetFreeInventorySpace / CanStoreNewItem），再销毁原饰品、生成卷轴
   → 提取成功后才销毁提取器（CONSUME_ESSENCE = true；改 false 即为可重复使用的工具）
```

## 4. ID 分配

已核对：`spellitemenchantment_dbc` 为空表，`spell_dbc` 与 `item_template` 的目标区块在库内均未被占用；
项目其它内容用的是 `@item_id_start = 99423+`（装备生成）等区块，不冲突。

| 对象 | 起始 ID | 当前占用 | 预留区块 | 表 |
| --- | ---: | --- | --- | --- |
| 附魔 `SpellItemEnchantment` | 30000 | 30000 ~ 30077（78 条） | 30000 ~ 30099 | `spellitemenchantment_dbc.ID` |
| 附魔法术 `Spell` | 94500 | 94500 ~ 94577 | 94500 ~ 94599 | `spell_dbc.ID` |
| 附魔卷轴 `item_template` | 63200 | 63200 ~ 63277 | 63200 ~ 63299 | `item_template.entry` |
| `spell_enchant_proc_data` | = 附魔 ID | 空（本批无命中触发） | 30000 ~ 30099 | `spell_enchant_proc_data.entry` |
| 饰品特效提取器 | 60105 | 60105 | — | `item_template.entry` |

> `generate.py` 会先 `DELETE` 整个预留区块（30000~30099 / 94500~94599 / 63200~63299）再插入，
> **请勿在这些区块内手工添加其它内容**。

## 5. 数据映射规范

### 5.1 附魔条目 `spellitemenchantment_dbc`

| 字段 | 取值 |
| --- | --- |
| `ID` | 30000 起，按特效法术去重后顺序分配 |
| `Charges` | 0（永久） |
| `Effect_1` | 3（EQUIP_SPELL）/ 1（COMBAT_SPELL） |
| `Effect_2` / `Effect_3` | 0（单效果） |
| `EffectPointsMin/Max_*` | 0（spell 类效果不需要点数） |
| `EffectArg_1` | 原特效 spell ID |
| `Name_Lang_deDE` / `Name_Lang_zhCN` | `|cffa335ee魄·<饰品名>|r`（紫色，与附魔窗口一致；两列都写保险） |
| `Name_Lang_Mask` | 16712190 |
| `ItemVisual` | 0（武器附魔无额外发光效果） |
| `Flags` / `Src_ItemID` / `Condition_Id` / `RequiredSkill*` / `MinLevel` | 0 |

### 5.2 附魔法术 `spell_dbc`

以 `Spell.csv` 中真实武器附魔法术 **35793（附魔武器 - 猫鼬）** 为模板整行复制，仅覆盖：

| 字段 | 取值 |
| --- | --- |
| `ID` | 94500 起 |
| `Effect_1` | 53（ENCHANT_ITEM，沿用模板） |
| `EffectMiscValue_1` | 对应附魔 ID |
| `EquippedItemClass` | `2`（武器） |
| `EquippedItemSubclass` | `2090495` = 0~20 位除 9/11/12 外全部置位（单手/双手/主手/副手/远程/法杖/匕首等） |
| `EquippedItemInvTypes` | `0`（真实武器附魔均为 0，目标过滤靠子类掩码） |
| `BaseLevel` / `MaxLevel` | `0`（不限制目标装备等级/装等，避免 `SPELL_FAILED_LOWLEVEL` / `HIGHLEVEL`） |
| `SpellIconID` / `ActiveIconID` | `241` / `0`（沿用模板法术 35793 的技能图标） |
| `Name_Lang_deDE` | `魄·<饰品名>`（`deDE` 列放中文，`enUS` 留空，其余语言列 NULL，口径同 `outputs/自定义混沌宝石/`） |
| `Description_Lang_deDE` | `永久性地为一把武器附魔，使其获得「<饰品名>」的特效。` |
| 其余 | 全部沿用模板（`CastingTimeIndex=1`、`RangeIndex=1`、`SpellVisualID_1=3182` 等） |

### 5.4 proc 数据 `spell_enchant_proc_data`

仅命中触发（`spelltrigger = 2`）的附魔需要：`entry = 附魔 ID`，`PPMChance = 原物品 spellppmRate`，
`customChance` / `procEx` / `attributeMask` 均为 0。

> **本批（饰品 78 条）没有命中触发特效，该表为空。** 生成脚本会自动追加，无需手工维护。

### 5.5 运行时映射表 `mod_trinket_essence_map`（本方案特有）

供运行时按「化妆品特效法术 → 附魔卷轴」查表，由生成脚本重建（`CREATE TABLE IF NOT EXISTS` + 全表 `DELETE` + 插入）：

| 字段 | 含义 | 运行时是否加载 |
| --- | --- | --- |
| `spell_id` | 饰品上的原特效法术 ID（主键） | ✅ 作 map key |
| `scroll_item` | 附魔卷轴 `item_template.entry`（生成给玩家的物品） | ✅ |
| `name` | 附魔显示名（紫色 `\|cffa335ee魄·…\|r`） | ✅ 用于提示消息 |
| `enchant_id` | `spellitemenchantment_dbc.ID` | ❌ 仅人工核对 |
| `enchant_spell_id` | 附魔法术 `spell_dbc.ID` | ❌ 仅人工核对 |
| `src_item` | 来源饰品 entry | ❌ 仅人工核对 |
| `src_spell_name` | 原特效法术名 | ❌ 仅人工核对 |

`src/TrinketEssence.cpp` 在 `WorldScript::OnStartup` 时一次性 `SELECT spell_id, scroll_item, name` 读进内存。

## 6. 交付物清单

落地由 `generate.py` 一次性产出：

1. 服务端 SQL：`modules/mod-random-enchants/sql/world/trinket_enchant_scrolls.sql`
   （`item_template` 卷轴 + `spell_enchant_proc_data` + `mod_trinket_essence_map`，
   以及清理 `spellitemenchantment_dbc` / `spell_dbc` 旧覆盖行的 `DELETE`）；
2. 客户端 DBC CSV（WDBX 导入用）：`dbc/TrinketEnchant_SpellItemEnchantment.dbc.csv`、
   `dbc/TrinketEnchant_Spell.dbc.csv`、`dbc/TrinketEnchant_Item.dbc.csv`；
3. 提取清单：`可用饰品特效清单.csv`。

另有手工维护的运行时部分：`src/TrinketEssence.cpp`（提取器脚本）与
`sql/world/trinket_essence.sql`（提取器道具 60105）。

## 7. 命名与显示

两个前缀是分开的（`generate.py` 的 `SCROLL_NAME_PREFIX` / `ENCHANT_NAME_PREFIX`）：

| 显示位置 | 数据来源 | 当前取值 |
| --- | --- | --- |
| 卷轴名（背包/聊天/物品提示） | `item_template.name` | `武器附魔·<饰品名>`，紫色由 `Quality = 4` 着色 |
| 附魔名（附魔窗口） | `SpellItemEnchantment.dbc` 的 `Name_Lang_deDE` | `\|cffa335ee魄·<饰品名>\|r` |
| 附魔法术名（日志/错误提示） | `Spell.dbc` / `spell_dbc` 的 `Name_Lang_deDE` | `魄·<饰品名>` |

## 8. 部署步骤

1. 执行两份服务端 SQL（均幂等，可重复执行；**顺序不能反**，60105 依赖映射表）：
   ```bash
   mysql -uroot -p acore_world < modules/mod-random-enchants/sql/world/trinket_enchant_scrolls.sql
   mysql -uroot -p acore_world < modules/mod-random-enchants/sql/world/trinket_essence.sql
   ```
2. 用 WDBX 把 `dbc/` 下 3 个 CSV 导入客户端对应的
   `SpellItemEnchantment.dbc` / `Spell.dbc` / `Item.dbc`，打成 MPQ 补丁下发。
   **服务端也要能读到同一份 DBC**（服务端 dbc 目录指向客户端 `Data`，或把改好的 DBC 拷到服务端 dbc 目录）。
3. **重新配置并编译 worldserver**（新增了 `src/TrinketEssence.cpp`，需重新 CMake 生成工程再编译）。
4. 重启 worldserver：附魔/法术走 DBC，`TrinketEssence` 在 `OnStartup` 加载映射表（日志打印加载条数）。
5. 发放道具：`additem <角色> 60105`（提取器）、`63200` 起（单个附魔卷轴）。

## 9. 注意事项与风险

1. **去重**：同一 proc 特效被多个饰品共用时按法术 ID 去重，只生成一份附魔条目；
   运行时多件饰品可提取到同一张卷轴。
2. **原法术依赖**：附魔的 `EffectArg_1` 直接引用原 proc 法术，不复制定义；原法术被删改则附魔失效。
3. **DBC 一致性**：附魔/附魔法术只存在于 DBC 里（`WRITE_DBC_TABLES = False`），
   服务端必须能读到打过补丁的那一份，否则施放卷轴会报 `unknown spell 945xx is casted, ignoring`；
   同理不要把 `spellitemenchantment_dbc` / `spell_dbc` 的旧覆盖行留在库里（它们会覆盖客户端 DBC）。
4. **EQUIP_SPELL 与 `spell_enchant_proc_data` 无关**：只有 COMBAT_SPELL（命中触发）才需要它。
5. **两段过滤**：运行时的装等阈值 `MIN_TRINKET_ITEM_LEVEL(200)` 需与 `generate.py` 的 `MIN_ITEM_LEVEL` 同步，
   否则会出现「列表里看得到但生成时没纳入」或反之的口径不一致。
6. **平衡性**：把饰品 proc 特效附到武器上会改变强度，需自行评估数值平衡。
