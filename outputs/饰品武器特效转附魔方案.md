# 饰品/武器特效转附魔道具方案

## 1. 需求概述

将「饰品」和「武器」上的**触发类特效（proc）**提取出来，制作为**附魔卷轴**，玩家使用卷轴后可将该特效**永久附魔到武器 0 槽位**。

范围约定：

- 物品等级 `ItemLevel >= 200`；
- 物品类别 `class IN (2 武器, 4 饰品)`；
- 特效类型：`spelltrigger = 1`（装备被动）与 `spelltrigger = 2`（击中触发）；
- **只保留真正的 proc 特效**（`ProcTypeMask > 0`），纯被动属性光环（如 `+治疗/+法伤/+攻强`）不做；
- 在 `Spell.csv` 中找不到定义的法术直接忽略；
- 道具形态：**附魔卷轴**（消耗品，右键使用 → 弹附魔窗口 → 选择武器 → 永久附魔到 0 槽位）。

## 2. 数据摸底

统计范围：`item_template` 中 `ItemLevel >= 200` 且 `class IN (2, 4)`，跨 5 个法术槽（`spellid_1..5` / `spelltrigger_1..5`），按法术 ID 去重后的结果：

| 特效类型 | 去重法术数 | 明细 |
| --- | ---: | --- |
| 装备被动（trigger=1） | 451 | 真 proc 特效 145；纯被动属性 304；未找到 2 |
| 击中触发（trigger=2） | 14 | 全部为 proc 特效 |
| **最终范围（真 proc 特效）** | **159** | 145（装备被动 proc）+ 14（击中触发） |

说明：

- 判定「真 proc 特效」的依据是 `Spell.csv`（或 `spell_dbc`）中该法术的 `ProcTypeMask > 0`；
- 纯被动属性光环 `ProcTypeMask = 0`、`ProcChance = 101`，属「装备时固定属性加成」，不在本次范围内；
- 未找到的 2 个法术为 `68496`、`72958`，按要求忽略。

## 3. 技术链路

服务端通过 `DBCStorage::LoadFromDB` 从数据库表**追加/覆盖** DBC 数据（server-side），客户端另需对应的 DBC 文件用于显示。整条链路如下：

```
饰品/武器特效 spell (item_template.spellid_i + spelltrigger_i)
   │  按 spelltrigger 映射附魔效果类型
   ▼
SpellItemEnchantment 条目  ──  trigger=1 → EQUIP_SPELL(3)
   │                           trigger=2 → COMBAT_SPELL(1) + proc 数据
   │  EffectArg = 原特效 spell 的 ID（效果完全复用原法术，无需复制）
   ▼
附魔法术 (Spell, Effect=53 ENCHANT_ITEM, EffectMiscValue=附魔ID)
   │  客户端据此弹出「附魔窗口」，服务端 EffectEnchantItemPerm 落到 0 槽位
   ▼
附魔卷轴 (item_template: class=0 / subclass=8, spellid=附魔法术, spelltrigger=0)
```

### 3.1 附魔效果类型映射

| 原特效类型 | 附魔 `Effect` 值 | 附魔 `EffectArg` | proc 数据 | 触发机制 |
| --- | ---: | --- | --- | --- |
| 装备被动（trigger=1） | `3` EQUIP_SPELL | 原特效 spell ID | 不需要 | 装备武器时施加原 proc 光环，由光环自身 ProcTypeMask/ProcChance 触发 |
| 击中触发（trigger=2） | `1` COMBAT_SPELL | 原特效 spell ID | 需要 | 击中时按 `spell_enchant_proc_data` 的 PPM 触发 |

关键点：

- **EQUIP_SPELL**：走 `Player::ApplyItemEquipSpell`，装备武器时把 `EffectArg` 指向的原法术作为光环施加给玩家；原法术本身是 proc 光环，触发逻辑完全复用，**无需** `spell_enchant_proc_data`。
- **COMBAT_SPELL**：走 `Player::CastItemCombatSpell`，需要 `spell_enchant_proc_data` 提供 PPM（`PPMChance` 取原物品的 `spellppmRate`）。

### 3.2 附魔到 0 槽位

`SpellEffects.cpp` 的 `EffectEnchantItemPerm` 中，`EffectMiscValue` 即为附魔 ID，最终写入 `Item::PERM_ENCHANTMENT_SLOT`（0 槽位）。因此每个附魔需要配一个 `ENCHANT_ITEM`（Effect=53）附魔法术，其 `EffectMiscValue` 指向附魔 ID。

## 6. 交付物清单

落地时由 Python 脚本一次性产出：

1. 服务端 SQL：`spellitemenchantment_dbc`、`spell_dbc`、`item_template`、`spell_enchant_proc_data`；
2. 客户端 DBC CSV：`SpellItemEnchantment.dbc`、`Spell.dbc`、`Item.dbc`（WDBX 导入用）；
3. 生成说明文档（命名规则、部署步骤）。

## 7. 命名与显示

- 附魔显示名、卷轴名均取原特效法术的中文名（`Spell.csv` 的 `Name_Lang_deDE` 列）；
- 统一加前缀 `附魔武器 - `；
- 若特效无中文名，回退英文名，再回退 `特效法术 #<id>`。

## 8. 部署步骤

1. 执行服务端 SQL（写库 `acore_world`）；
2. 将客户端 DBC CSV 用 WDBX 编辑器导入对应 DBC，生成补丁下发客户端；
3. 重启 worldserver 使 `LoadFromDB` 生效；
4. 发放卷轴（GM 命令 `additem` 或后续挂到 `npc_vendor`）。

## 9. 注意事项与风险

1. **去重**：同一 proc 特效可能被多个饰品/武器共用，按法术 ID 去重，只生成一份附魔条目。
2. **EQUIP_SPELL 与 COMBAT_SPELL 不共用 proc 数据**：只有击中触发类才写 `spell_enchant_proc_data`，装备被动类由原法术自身 proc 逻辑驱动。
3. **原法术依赖**：附魔 `EffectArg` 直接引用原特效 spell，若原法术后续被删除/改动，附魔会失效；本次仅引用，不复制法术定义。
4. **客户端一致性**：服务端 `LoadFromDB` 与客户端 DBC 需同步更新，否则附魔显示名/图标不一致或无法施放。
5. **平衡性**：把饰品 proc 特效附到武器上会改变强度，需自行评估数值平衡。
